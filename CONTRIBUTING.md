# Contributing

Start from the named release for the book exercise you are following. Keep a change focused, explain the behavior it corrects, and add a meaningful regression check when behavior changes. Preserve the deliberately faulty exercise starters unless the assignment itself is being corrected.

Use the lockfile and Node.js24. Run the relevant named checks; database tests need the dedicated local teaching MongoDB. Do not run paid coding/model experiments merely to change documentation. Never include real organizational data, account traces, model weights, secrets or generated dependency folders.

A contribution should distinguish deterministic test results from measured model behavior. Preserve failures in any research contribution and describe its scope rather than claiming general model superiority. Public book-edition tags are immutable; corrections receive a new version.
